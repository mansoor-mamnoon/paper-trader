                How it improves itself

                1. Mine. Once a week it reviews how the live strategy traded: wins, losses, what the analyst said, how buys before earnings behaved.
                2. Propose. The AI suggests one small change, such as a wider stop, an earnings blackout, or a rewritten playbook. Every value must stay inside fixed bounds.
                3. Test. The change trades a separate $1,000 shadow account on the same data for at least two weeks.
                4. Decide. It replaces the live strategy only if it beats it by a clear margin with similar risk. The old strategy keeps running and wins its seat back if the change turns out to be luck.

                Position size, the five-slot cap, costs and the 60-day end are written in code. No proposal can change them.

                  How it works

                  A fake $1,000, a committee of model calls, and nothing hidden.

                  1. Scan and screen

                    After the US close the program loads a rotating batch of US stocks, their daily prices, the earnings calendar, headlines and, when a contact address is configured for the SEC, recent filings and industry codes. Hard gates come first and no model can loosen them: the price must be at least $5, average daily traded value at least $5M over 30 sessions, and there must be no earnings report, FDA decision or restructuring (bankruptcy, reverse split, merger, delisting) within 7 days either side. Survivors then need the trend and momentum screen shown in the Strategy lab. A queued buy is checked against the gates again before it fills.

                  2. Triage

                    The model scores the survivors in small batches for how specific and recent their catalyst is, and keeps the best few as finalists.

                  3. Research agents

                    For each finalist an agent decides what to look up next: read a filing, pull older headlines, inspect price action. Each step is shown on The Desk tab.

                  4. Bull and bear

                    Two calls argue the stock for and against, using only the evidence gathered.

                  5. The judge

                    A portfolio manager writes out its reasoning, calls the market regime, and picks and states what would prove it wrong. Money splits across five slots of 20%, and a formula, never the model, sizes each one: a risk-off call halves it, a stock with more than 8% daily volatility gets 8%/σ of it, and no industry may pass 30% of equity. An order fills at the next session's open with fees and slippage, and the following evening's run records the fill. A session counts as finished from 4:30 pm New York time, so each evening run sees that day's prices.

                  6. Doctor, memory and scorecard

                    A doctor re-checks every holding and may exit or tighten a stop. Closed trades become lessons. Every pick, veto and near miss is scored against SPY, and shadow accounts at lower desk depths show whether each layer earns its place.

                  Independent models

                  Each decision is made by a different open-weights model from a different company: triage, research, the bull case, the bear case, the judge, the doctor, the post-mortem, the strategy proposer and the single-shot analyst. A model that reads the debate did not write both sides of it. The Desk tab lists who decides what, and every model file is pinned to an exact version and checked by hash.

                  The runner holds one model at a time, so the work runs in blocks and swaps models between them.

                  Same prompt, same answer

                  Every model call uses greedy decoding with a fixed seed, and each model file is checked against a pinned hash before it loads. When a model loads it answers the same small prompt twice. If the two answers ever differ, the Ops tab shows the model as unstable. The CPU of each run is logged, because different machines can round differently.

                  Why it keeps running

                  The job runs on GitHub's free runners. GitHub can delay or drop scheduled runs (on 9 November it dropped two in one evening), so the main trigger now lives outside GitHub: every 30 minutes a small script on a Mac, or a free Cloudflare cron, checks whether the latest session has been processed and starts a run through GitHub's API if not. The GitHub schedule stays as a backup. A run skips itself when the account already ran after the latest session settled at 4:30 pm New York time, so extra triggers cost nothing. A watchdog starts a run each morning if one was missed, and every run re-enables the schedule so GitHub never pauses it for inactivity.

                  Reading the Ops tab

                  Start at the top: the status word says whether the last run finished cleanly, and the bar shows how much of its time budget it used. "Where the time went" shows each stage of that run, with triage, research, bull and bear indented inside the desk's prepare stage, and "Bottlenecks" shows which stage is slowest on average across the last 30 runs. While a run is going, the Actions log prints each step as it happens and a heartbeat every minute, so a slow run and a stalled one look different. If a model's latency or error count climbs, or a data source starts failing, it shows in the tables below before it shows in the results. The raw logs are downloadable.

                  What this cannot tell you

                  • Sixty days is too short to separate skill from luck.
                  • Prices are delayed and come from a free source with no guarantees.
                  • Stops are checked on daily closes, so a gap can cost more than 4%.
                  • Real markets add queues, outages and price impact that this model leaves out.
                  • The page refreshes when GitHub Actions publishes after each US session. It can run late or fail, and the last good snapshot stays up.

                  This is a simulation and not financial advice.
